# Threads Digest

Автоматический поиск популярных тредов в Threads и подготовка контента
для Telegram-каналов (RU/EN) и YouTube Shorts (RU/EN).
Каждая публикация ведёт на [threadsviewer.online](https://threadsviewer.online)
и в бота [@threadsreaderbot](https://t.me/threadsreaderbot).

> Полное ТЗ — в исходном задании (версия 1.0, 22.11.2026).
> Как ТЗ ложится на Cloudflare — см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Стек (Cloudflare)

- **Workers** (TypeScript) — сборщик, оценка, бот-редактор, публикация, админка
- **D1** — база (посты, замеры, кандидаты, материалы, публикации)
- **R2** — карточки, субтитры, ролики (30 дней)
- **Queues + Cron Triggers** — планировщик и фоновые задачи
- **Workers AI** — нейросеть по умолчанию (или OpenAI-совместимый API)
- Внешний рендерер с ffmpeg — только для сборки Shorts (в Workers его нет)

## Быстрый старт

```bash
npm install

# 1. Создать инфраструктуру Cloudflare
npm run db:create            # запомните database_id → вставьте в wrangler.toml
npx wrangler r2 bucket create threads-digest-media
npx wrangler queues create threads-digest-jobs

# 2. Миграции
npm run db:migrate:local     # локально
npm run db:migrate           # в прод

# 3. Секреты (НЕ коммитятся!)
cp .dev.vars.example .dev.vars   # заполнить токены
# или: npx wrangler secret put TELEGRAM_EDITOR_BOT_TOKEN

# 4. Запуск и тесты
npm run dev                  # wrangler dev → http://localhost:8787
npm test                     # vitest: оценка, фильтры, парсер, язык, подписи, карточки, Shorts, планировщик
npm run typecheck
```

## Маршруты Worker'а

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | Проверка живости |
| POST | `/webhook/telegram` | Бот-редактор (только `ADMIN_IDS`) |
| GET/POST | `/admin/accounts` | Аккаунты-сборщики (cookies, прокси, язык) |
| GET | `/admin/authors` | Авторы (seed / стоп-лист) |
| GET | `/admin/top?lang=ru` | Топ кандидатов по `score` |
| GET | `/admin/config` | Конфиг приложения |
| GET | `/media/*` | Карточки и ассеты из R2 |

Админка требует заголовок `X-Admin-Key: <ADMIN_API_KEY>`.

## Бот-редактор

Команды: `/queue` · `/top ru|en` · `/accounts` · `/stats` · `/takedown <код>`

Кнопки на черновике TG: ✅ опубликовать · 🕒 в очередь · ✏️ изменить текст ·
🔁 переписать · 🖼 без/с фото · 🙈 анонимно/с ником · 🗑 отклонить · 🚫 автор в стоп-лист.
На черновике Shorts: ✅ загрузить · 🕒 в очередь · ✏️ заголовок ·
🔁 другая озвучка/фон · ⬇️ скачать файл · 🗑 отклонить.

## Как устроен конвейер

```
Аккаунты-сборщики (cookies + прокси-шлюз)
  → Cron (5 мин) → Queues → сбор ленты/авторов/поиска/трендов (JSON GraphQL)
  → D1: posts + post_snapshots (замеры через 1/3/6/12/24 ч)
  → Оценка: score = hot · lift^0.5 · (1+0.5·discuss) · k_контента  (src/lib/scoring.ts)
  → Фильтры (реклама, 18+, политика, стоп-лист…)  (src/lib/filters.ts)
  → Нейросеть: перевод, пересказ, сценарий Shorts  (prompts/*.md)
  → Карточка SVG 1080×1350 (R2) + подпись TG с UTM
  → Бот-редактор: подтверждение → публикация в TG / YouTube
  → Статистика → веса авторов/тем (×0.7–1.5)
```

## Конфигурация

- `config/default.json` — коэффициенты оценки, фильтры, расписание слотов,
  бюджет страниц, параметры Shorts и карточек.
- `wrangler.toml` — D1/R2/Queues/Cron/Workers AI, провайдеры.
- `prompts/*.md` — промпты нейросети (правятся без программиста).
- `seeds/` — стартовые авторы и ключевые слова на каждый язык.

## Этапы внедрения (по ТЗ)

1. **Поиск** — аккаунты, источники И1–И4, замеры, оценка, «Топ-20 дня» в бот-редактор. ✅ Реализовано.
2. **Telegram** — перевод/пересказ, карточки, черновики, очередь, публикация, UTM. ✅ Реализовано.
3. **Shorts** — сценарий, субтитры ASS, метаданные, загрузка на YouTube (private до аудита). Монтаж — внешний рендерер (см. ARCHITECTURE.md).
4. **Статистика** — сбор просмотров TG (MTProto-скрипт) и YouTube Analytics, недельный отчёт, веса. Каркас готов (`src/stats/weights.ts`).

## Что нужно от заказчика

1. 5 аккаунтов Threads (2 RU, 2 EN, 1 запасной) и их cookies (JSON из расширения).
2. Прокси по одному на аккаунт + HTTP-шлюз (см. ARCHITECTURE.md, раздел «Per-account proxy»).
3. Два Telegram-канала и токен бота-издателя (бот — админ каналов).
4. Два YouTube-канала, проект в Google Cloud с YouTube Data API v3, OAuth-токены.
5. Ключ нейросети (если не Workers AI) и TTS.
6. Стартовые списки: 100–300 авторов и 30–50 ключевых слов на язык.
7. Оформление: названия каналов, логотип, голоса, фоны и музыка с лицензией.

## Открытые вопросы (раздел 19 ТЗ)

1. Политика и война — исключать полностью или разрешить нейтральные посты? (по умолчанию — исключать)
2. RU-канал: только русскоязычные треды или + переводы популярных EN? (настройка `allowTranslatedEn`)
3. Порог анонимизации 10 000 подписчиков — подходит?
4. Частота 3–5 постов и 1–2 ролика в день — подходит?
5. Голоса: мужской или женский?
6. Старт только с подтверждением человека? (рекомендуется, по умолчанию — да)
7. Названия каналов и бренд?

## Лицензия и риски

Сбор данных может нарушать правила Threads — аккаунты-сборщики отдельные,
только чтение, умеренная частота. Публикуются короткие цитаты с указанием
автора и ссылкой на оригинал; по жалобе — снятие в течение 24 часов
(`/takedown`). Подробнее — раздел 16 ТЗ.
